## 未解决

- [ ] 覆盖率仍未达到高质量收敛水平。
  - 当前 Line `64.41%`，Branch `54.36%`。
  - 目标：后续至少把 branch coverage 提升到可接受门槛，并解释无法覆盖的代码。

- [ ] 非法配置和 assert 路径尚未系统验证。
  - 需要 death tests 或独立子进程测试，避免默认回归因 abort 中断。
  - 示例：非法 sector line size、非法 set-index 参数、非法 write policy 组合。

- [ ] `cache_stats` fail reason 仍缺少精确反查验证。
  - 当前已覆盖 reservation fail 汇总，但 `MISS_QUEUE_FULL`、`MSHR_ENTRY_FAIL`、`MSHR_MERGE_ENTRY_FAIL`、`MSHR_RW_PENDING` 等原因需要逐项断言。

- [ ] sector cache 状态组合仍需扩展。
  - 当前覆盖局部 sector miss 和 readable 关键路径。
  - 后续需要覆盖更多 dirty sector mask、multi-sector fill、sector eviction/writeback 组合。

- [ ] texture cache 极限路径仍需扩展。
  - 当前覆盖 miss pipeline、hit reserved、FIFO/ROB backpressure。
  - 后续需要覆盖 result FIFO 满、SECTOR_TEX_FIFO pending_read、多返回顺序等路径。

- [ ] MSHR 长 trace 和随机 differential/property 测试仍不足。
  - 当前有 fixed seed property trace。
  - 后续需要多 seed、长 trace、读写混合、与参考模型对照。

- [ ] set-index/hash golden 地址集还不够大。
  - 当前只校验选定地址。
  - 后续需要覆盖更多地址、不同 nset、边界地址和冲突模式。

- [ ] `llvm-cov` 报告中仍有 `18 functions have mismatched data` 警告。
  - 当前 `coverage.sh` 成功并输出报告。
  - 后续需要判断是多 binary profile 合并造成的可接受警告，还是需要拆分/调整覆盖率采集方式。

## 下一步优先级

1. 建 death test 框架，覆盖非法配置和 assert 路径。
2. 按 fail reason 补齐精确统计断言。
3. 扩展 sector/texture 极限路径。
4. 增加多 seed randomized/property 回归。
5. 继续提升 branch coverage，并把每次提升同步到本文档和 `doc/verification/coverage_baseline.md`。
