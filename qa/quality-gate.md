# OpenCache 质量门禁

本文件定义 OpenCache 交付前必须满足的质量要求。

## 1. 文档门禁

| 检查项 | 要求 |
|--------|------|
| 文档位置 | 项目级文档放 `doc/`，版本级文档放对应版本的 `doc/` |
| 需求记录 | 新需求必须写入 requirements 文档 |
| 原始需求 | requirements 中必须保留用户原始需求 |
| 拆解需求 | requirements 中必须有可执行的拆解需求 |
| 验收标准 | 每条需求必须有验收标准 |
| 链接更新 | 文件移动后必须更新相关索引和引用 |

## 2. 代码门禁

| 检查项 | 要求 |
|--------|------|
| 变更范围 | 只修改与需求相关的文件 |
| 双版本影响 | 判断是否影响 `gem5_cache` 和 `gpgpusim_cache` 两个版本 |
| 废弃内容 | 废弃内容放入 `deprecated/`，不要和当前实现混放 |
| 构建脚本 | 不破坏 `run.sh` 和 CMake 构建路径 |

## 3. 测试门禁

交付前必须回归所有用例：

```bash
./gem5_cache/run.sh
./gpgpusim_cache/run.sh
```

通过标准：

1. 命令退出码为 0。
2. 测试输出无失败断言。
3. 新增功能有对应测试或明确说明为什么无需新增测试。
4. 如果测试无法运行，交付说明必须记录阻塞原因。

## 4. 交付门禁

交付说明必须包含：

1. 变更摘要。
2. 关键文件列表。
3. 验证命令和结果。
4. 未解决风险。

## 5. 例外处理

如果无法满足某项门禁，必须在交付说明中写明：

1. 哪项门禁未满足。
2. 原因。
3. 后续补救动作。
